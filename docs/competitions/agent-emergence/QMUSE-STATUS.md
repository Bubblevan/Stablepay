# QMuse：可选工具及接入状态

核对日期：2026-10-28。

**QMuse不是参赛必做集成，不应将未导入QMuse列为投稿阻断项。** 当前选择自有React、Go后端与HTTPS服务器路线；赛制核验和来源见[两场比赛要求复核](../RULES-CHECK-2026-10-28.md)。

QMuse本身尚未登录、导入或发布，没有平台作品地址；这是可选路线未实施，不是核心MVP缺失。

[官方CLI说明](https://www.npmjs.com/package/@qmuse/qmuse-cli)支持 React 项目导入，以及外部后端、QMuse云服务两种配置。本轮从官方 npm registry 核对 CLI 版本为 `1.0.7`。没有安装CLI、执行登录或创建云资源。

当前校园版的模型调用、引用校验、报告持久化和导出由 Go Runtime 提供，前端通过同源 `/api/mvp/*` 调用，使用 HttpOnly、SameSite Cookie。只导入 React 源码不会自动把 Go 服务变成 QMuse 云函数，也不能将本机 `127.0.0.1` 地址提供给评委访问。

只有将来明确选择QMuse时，才需要以下接入顺序：

1. 用户恢复公网服务后，验证 HTTPS Runtime、允许来源、会话与报告下载。QMuse外部后端接入还需确认平台代理方式；跨域不能仅替换URL或暴露内部Token。
2. 在明确的用户账号与空间中完成CLI登录，检查空间及云服务权益。登录确认由用户在官方页面完成。
3. 仅以 `stablepay-frontend` 为导入根，不上传仓库根目录、`.env`、私钥、测试Cookie或订单快照。
4. 配置经过实际验收的外部服务，或单独评估迁移云函数；不把前端可构建当作后端已READY。
5. 保留导入任务、应用绑定和访问地址；在平台页面完成真实模型抽取、人工确认、预审、下载、刷新和权限拒绝验收后，再标记完成。

用户决定自行录屏。新服务器已部署PAYATHON沙箱与回调，校园AI工作台继续在本机运行；详情见[公网沙箱](../PUBLIC-SANDBOX.md)。当前不启动QMuse发布或其云资源流程。
