# 两场支付宝比赛：赛制与 QMuse 要求复核

核验日期：2026-10-28，Asia/Shanghai。

## 结论

**QMuse 是可选开发和托管工具，不应列为当前项目参赛的必做集成或投稿阻断项。** 已有 React、Go 后端和自有 HTTPS 服务可以继续使用。报名、作品信息填写、审核与访问链接等赛事流程仍需完成，工具选择和报名平台不是同一件事。

## 对照

| 项目 | 支付宝智能体涌现奖 | PAYATHON 2026 / AI付黑客松 |
| --- | --- | --- |
| 核心方向 | 生活场景智能服务；生活好帮手、消费新体验 | AI产品商业化、支付、收款与交付 |
| 参赛形态 | 公开说明允许多种开发工具，不限于QMuse；可提交可公开访问的作品链接 | 网页、App、桌面应用等；部分探索赛道形态不限 |
| QMuse | 示例工具，不是强制条件 | 合作伙伴及开发资源之一，官网参赛规则未要求使用 |
| 分组 | 季度入围与年度大奖 | VibePay、SkillPay、MachinePay、TokenPay、AgentPay |
| 主体 | 生活好帮手面向个人开发者；消费新体验面向商家、机构 | 个人或2–5人团队 |
| 支付 | 本轮未核到生活好帮手统一必须接入支付的条款；不能把另一场的收款要求套用过来 | 官网明确要求接入相应支付能力；评审关注真实有效付费与交易交付 |
| 时间 | 最新首季延长公告本次未读到，不能在11月10日与12月6日之间自行下定论 | 报名12月1日23:59:59截止，作品提交12月9日23:59:59截止，12月26日决赛 |
| 作品限制 | 最新完整细则本次未独立读取 | 每赛道最多10件独立作品，同一作品不得跨赛道重复投稿；同赛道同主体最多1件作品获奖 |

## 来源及证据强度

1. [PAYATHON官方赛事页](https://aipay.alipay.com/community/events/payathon-2026)：本次重新读取赛道、时间、主体、评审和公开参赛规则。QMuse在合作伙伴与权益处出现，未作为技术必选条件。页面隐藏的开发预览、模拟报名、占位密钥不是实际报名或产品开通证据。
2. [《AI付黑客松活动细则》官方链接](https://render.alipay.com/p/yuyan/180022670000190962/index.html)：本次仍未读取到正文，详细资格与权利条款不作推断。
3. [新华网客户端刊载的2026外滩大会发布内容](https://app.xinhuanet.com/news/article.html?articleId=20260910a9b950cc103e4db4b2ec3fd32d4dc003)：明确说明开发工具不限，QMuse是举例，介绍两类方向和季度/年度赛程。
4. [IT之家关于支付宝发布的报道](https://www.ithome.com/1/000/848.htm)：明确提到公开访问URL和本地研发CLI提报。它是发布报道，不替代最新完整活动细则。
5. 旧入口 `https://emerge.alipay.com/`：本次浏览器访问被转至支付宝Not Found页。因此没有将第三方赛事日历的截止时间当作官方最新确认；最终投递时间应在支付宝阿宝的赛事入口或可访问的新公告核对。

## 对当前产品的影响

- 校园分支继续做可追溯AI抽取、人工确认和确定性采购预审；无需为了QMuse迁移Go后端。
- PAYATHON继续使用payment-service的CNY沙箱扩展；普通电脑网站收银台不能直接冒充完整AgentPay接入。真实支付、产品权限、官方支付工具和履约证据仍需按所选赛道验收。
- 两个分支可以共享工程代码，但PAYATHON内部跨赛道重复作品限制必须遵守。跨两个独立活动的重复参赛限制本轮未读到完整条款，不作保证。
- 自有HTTPS访问是当前实施路线。QMuse接入从“待完成门槛”调整为“可选项”。
