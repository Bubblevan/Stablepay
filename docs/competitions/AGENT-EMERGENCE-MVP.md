# 校园采购守门员：审查修正与本地验收

日期：2026-10-28（Asia/Shanghai）。分支：`contest/alipay-agent-emergence-2026`。

用户提供的审查针对 `3cfbffa`。本轮在已合并共享服务的 `ceceeef` 上修正，保留现有 Runtime 的模型传输和确定性采购核验。不重写 StablePay，不要求支付，不引入校园 ERP。

## 实现的闭环

1. 分别粘贴活动需求与报价文本，显式点击 AI 抽取。仅此操作将文本发送给已配置的模型。
2. 模型输出结构化草稿。服务端逐条验证原文片段、数字依据、来源类别和字符区间，保存来源 SHA256、模型信息和返回摘要。错误引用、未知字段及模型自带审批字段会被拒绝。
3. 展示原文引用和待确认问题，允许人工编辑。缺失数量和单价不被当作免费或零数量；AI 不确认审批、不设置任何人工核验记录。
4. 用户对照原文明确确认当前清单，服务端运行预算、规格及证据状态规则，并记录人工修改字段。修改后旧结果失效，必须重新确认预审。
5. 下载服务端生成的 Markdown，包含当时的输入、风险、AI 引用、来源原文、人工修改与版本。不同浏览器会话不能读取对方记录。

## 本机启动

在仓库根目录执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\stop-procurement-mvp.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-procurement-mvp.ps1 -Competition campus -UseLLM
```

打开 `http://127.0.0.1:8093/campus`。校园模式只运行 Runtime，不启动 payment-service，不调用支付宝或原链上支付。无需 MySQL、Redis、RocketMQ、Docker。

`-UseLLM` 只从根 `.env` 导入 `LLM_PROVIDER`、`LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL` / `LLM_MODEL_ID`；不执行文件中的代码，不加载支付宝或钱包配置，不在输出打印密钥。进程环境变量优先。Provider 默认 `openai-compatible`。不用该开关时可手动录入、预审，但会明确显示模型未配置，不提供伪造 AI 结果。

原文与服务端快照保存在忽略目录 `.local-run/procurement-mvp/runtime-campus-local.json`，草稿存在浏览器 localStorage。刷新恢复草稿；服务重启保留快照；清除 Cookie 后无法用原会话读取记录。恢复合成示例不会删除服务端历史。MVP 最多保留200次抽取、500次预审，达到上限需人工导出归档。此方案适合当前本机演示，未作为多用户高并发持久化验收。

## 证据和规格的修正

- 三种证据状态：用户声明、有材料但未核验、人工核验记录。后者要求引用、复核人和有效时间，仍是使用者记录，不表示平台已验证文件真伪。
- 文件名、URL、预算依据文本和可开票勾选都不能独立解除证据待办。合成资料即使填写人工记录也会继续提示演示范围。
- 明确标注的毫米、厘米、米支持精确换算：`3m × 0.8m` 等价于 `300cm × 80cm`。尺寸分隔符保留；不把 `3×08` 与 `30×8` 混为一谈。模糊单位、材质、适用性不由 AI 自动批准。
- 非法数量、负价、超精度金额会拒绝预审。预算空缺产生阻断项，不把它当作零预算正常通过。

适用范围仅为该校已登记校级学生社团使用校团委社团活动专项经费。用户须选择参考包、填写一致学校名并确认资金范围，才展示该包的条款核对待办。只提示预算前置流程、材料时限和票据核对；不覆盖全文、不自动判定日期或报销资格、不跨学校推广。默认不加载任何校规。使用前应再核对学校最新通知。
